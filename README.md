# Blue Computer Services

Landing page for Blue Computer Services, a Livermore, California IT company
that manages and secures business networks for small and medium-sized
companies. Owner Randall Nerison has supported small business networks since
2002.

A one-page site in plain HTML, CSS and JavaScript with a control-room look:
an office network diagram in the hero, a services console, a sample audit
scanner, a managed IT vs. break-fix comparison, a coverage map of the office,
a symptom picker and a searchable FAQ.

## What's here

```
index.html          The site. Generated by build.ps1. Open it or serve it.
site.webmanifest    Web app manifest (icons, theme colour).
assets/images/      Logo (lossless WebP at 1x/2x/3x), wave mark, favicons and share image.
src/                Sources the site is built from. Edit these, not index.html.
wordpress-theme/    The same site as an installable WordPress theme (PHP).
docs/WIREFRAME.md   The wireframe and verified facts the page was planned from.
build.ps1           Rebuilds index.html and regenerates the theme.
.nojekyll           Tells GitHub Pages to serve assets/ verbatim.
```

`brand/` (the logo and favicon exactly as supplied) stays on this computer
only. It is listed in `.gitignore`, so it is never pushed.

## View it locally

Open `index.html` in a browser. For the fonts and manifest to load reliably,
serve it over HTTP rather than the `file://` protocol, for example with the
VS Code Live Server extension.

## Host it on GitHub Pages

1. Create an empty repository on GitHub (no README, licence or .gitignore, so
   the first push doesn't conflict).
2. Push this folder to it (see below).
3. In the repo, go to **Settings > Pages**.
4. Under **Build and deployment**, set **Source** to *Deploy from a branch*, pick
   the `main` branch and the `/ (root)` folder, and save.
5. The site goes live at `https://<your-username>.github.io/<repo-name>/` within
   a minute or two.

The folder is already a git repository with its work committed on `main`, so
you only need to add the remote and push:

```bash
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

`index.html` is at the repo root and every path in it is relative, so Pages
serves it as the home page with no extra configuration, including from a
`/<repo-name>/` sub-path.

To use the client's own domain later, add it under **Settings > Pages > Custom
domain** and point the DNS at GitHub as the page there describes.

## Editing the site

`index.html` is generated with all CSS and JS inlined, so do not edit it by hand.
Edit the sources instead:

```
src/_head.html      <head> contents: title, meta, favicons, fonts, structured data
src/_body.html      Page markup and all visible copy
src/css/theme.css   All styles (every colour is a token at the top)
src/js/main.js      All interaction (boot intro, cursor, rail, Ctrl/Cmd+K palette,
                    hero diagram, services console, scanner, comparison, coverage
                    map, process track, symptom picker, FAQ, forms)
```

Then rebuild:

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

That regenerates `index.html`, rewrites `wordpress-theme/style.css`,
`wordpress-theme/front-page.php` and `wordpress-theme/assets/js/main.js` from the
same sources, and mirrors `assets/images` into the theme, so both deliverables
stay in step. `functions.php` and `index.php` are edited in place. The build
stops if an em or en dash slips into the copy, if a colour is hardcoded outside
`:root`, if a CONFIRM placeholder sits inside an HTML attribute, if the CSS has
an unbalanced quote, or if the page points at a file that doesn't exist (with
exact filename case, since GitHub Pages is case-sensitive). It finishes by
printing how many `CONFIRM` placeholders are left.

## The WordPress theme

`wordpress-theme/` is a self-contained theme (`style.css`, `front-page.php`,
`functions.php`, `index.php`, `screenshot.png`, `assets/`). GitHub Pages ignores
it because Pages does not run PHP. To use it, copy the folder into a WordPress
install under `wp-content/themes/` (or zip it and upload under **Appearance >
Themes**), activate it, then set a static front page under **Settings > Reading**.

In WordPress the contact form posts to `admin-post.php` and emails the message
with `wp_mail`. It goes to info@bluecomputerservices.com by default and can be
changed under **Settings > General > BCS contact email**. Make sure the host can
send mail (an SMTP plugin is the usual fix if it can't). Stylesheet and script
are versioned by file date, so browsers pick up changes straight away.
Functions are prefixed `bcs_`.

## Notes

- The static site has no server, so on GitHub Pages the contact form and the
  "call me back" strip open the visitor's email app with the details filled in,
  addressed to info@bluecomputerservices.com. Change `$LeadEmail` in `build.ps1`
  for the form and `data-to` on `#cb` for the strip. The WordPress theme sends
  the contact form for real.
- No photos. The hero diagram, service schematics, coverage map and every
  other visual are inline SVG and CSS in the brand colours.
- Colours: the logo is one flat blue, `#0099FF`, used on buttons with navy text
  because white text fails contrast on it. The navy is built on the same hue.
  Teal means "all clear"; amber and red are used for status only.
- Fonts (Rajdhani, IBM Plex Sans, IBM Plex Mono) load from Google Fonts, so the
  live site needs an internet connection for the intended typography.
- The logo is used as supplied, trimmed to its visible box, colours untouched.
  Favicons were generated from the supplied BCS Favicon.png.
- The boot intro shows once per browser session. Motion respects
  `prefers-reduced-motion`: the intro, cursor, scramble, loops, scan lines and
  typing effects are off and final states show at once. The custom cursor never
  runs on touch screens.
- The office-hours light in the owner section uses placeholder hours (Monday to
  Friday, 8 to 5 Pacific) until the real hours are confirmed.
- The share image (`og:image`) uses a relative path. Social sites need a full
  URL, so once the live address is known, change it in `src/_head.html` to
  `https://<your-domain>/assets/images/og-image.jpg` and rebuild.

## Before launch

Every unverified detail shows on the page as an amber dashed
`==[CONFIRM: ...]==` chip. Search `src/_body.html` for `CONFIRM`, replace each
with the real answer (or delete the sentence), then run `build.ps1` until it
reports 0. Also confirm whose line (925) 887-0812 is.
